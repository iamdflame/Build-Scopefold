Audience:

CORE PROBLEM

Signed scopes of work contain deliverables, obligations, approvals, dependencies, dates, revision limits, and payment terms. After signature, teams manually rebuild that information across project-management, payment, email, and client-portal tools. Important contract language becomes disconnected from daily execution.

SOLUTION

Scopefold transforms a signed scope into:

- Reviewed obligations
- Milestones
- Tasks
- Dependencies
- Payment requests
- Client approvals
- Client portal views
- External execution through Stripe, Resend, and Linear
- Immutable execution receipts
- A complete proof chain back to the original contract language

The defining chain is:

SOURCE CLAUSE
→ REVIEWED OBLIGATION
→ OPERATIONAL OBJECT
→ EXTERNAL ACTION
→ IMMUTABLE RECEIPT

Every operational object must answer:

“Why does this exist?”

Every external receipt must answer:

“What exact contract language authorized this action?”

This provenance chain is Scopefold’s primary innovation. Do not reduce Scopefold to a generic project-management dashboard, PDF summarizer, AI wrapper, or contract checklist.

NON-NEGOTIABLE PRODUCT PRINCIPLES

1. The complete demo works with zero API keys.
2. Simulated actions are always labeled Simulated.
3. Missing credentials never block startup.
4. Configured provider failures never silently fall back to fake success.
5. Human review is required before contract interpretation becomes operational work.
6. Every generated operation has source evidence.
7. Successful external writes are never rolled back because another provider failed.
8. Every remix starts with rich deterministic sample data.
9. The app must be useful before authentication or connector setup.
10. There must be no marketing landing page. Open directly into the working product.

CLIENT PORTAL AUTHORIZATION

FOLD ALGORITHM

The Fold must be deterministic after review.

Rules:

- Milestone obligations create milestones.
- Task obligations attach to the nearest relevant milestone.
- Payment obligations create payment requests.
- Approval obligations create approval requests.
- Dependency obligations create dependency edges.
- Constraints add risk and blocking metadata.
- Dates become due dates.
- Currency values become integer-cent amounts.
- Evidence links propagate to every resulting object.
- A resulting object without evidence is a validation failure.
- Repeated Fold requests with the same reviewed-input hash and policy version return the same result.
- Committing a Fold creates a versioned fold_run.
- A later Fold supersedes an earlier version but never deletes historical receipts.
